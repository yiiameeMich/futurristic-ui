## Purpose

`@yiiameemich/futurristic-ui` is a Nuxt module providing a reusable UI component kit for internal company projects, consumed as an npm package. One module, several visual identities: each consuming app picks a **style mode** (`defend`, `guard`, `expert`; `validate` planned) in its `nuxt.config`, and every component restyles accordingly — no per-app forks, no copy-pasted components.

Priorities, in order:

1. **Reusability** — components are mode-agnostic and work in any consuming Nuxt app unchanged.
2. **Optimization** — the headline invariant: **inactive-mode CSS is emitted at build time but never fetched by the browser.** An app running `defend` downloads zero bytes of `guard` or `expert` styles.

## Non-goals

- Light/dark color schemes. Modes are brand themes, one axis only. A second axis (`data-fu-scheme`) is *reserved* in the token grammar ([01 §8](01-style-modes-and-theming.md)) but not planned for implementation.
- Theming beyond the token system — no CSS-in-JS, no runtime style generation, no consumer-supplied arbitrary themes.
- Standalone (non-Nuxt) Vue usage.

## System map — what `module.ts` does

Six responsibilities, in setup order ([src/module.ts](../../src/module.ts)):

| # | Responsibility | Mechanism |
|---|---|---|
| 1 | SVG imports | `extendViteConfig` registers `vite-svg-loader` (`defaultImport: "url"`); `Icon.vue` opts into `?component` per import |
| 2 | Expose initial mode | `runtimeConfig.public.futurristic = defu(existing, { mode })` |
| 3 | Shared utility CSS | Pushes `runtime/assets/shared/radius-utilities.css` to `nuxt.options.css` — the **only** globally bundled stylesheet |
| 4 | Component registration | `addComponentsDir` on `runtime/components`, `prefix` option (default `Fu`), `global: true` |
| 5 | Composables | `addImportsDir` on `runtime/composables` → auto-imported `useFuturristic()` |
| 6 | Mode binding | `addPlugin` → `runtime/plugins/futurristic-init` |

## Runtime flow

Drawn once here; other docs reference it.

```
nuxt.config  futurristic: { mode }
        │
        ▼
runtimeConfig.public.futurristic.mode
        │
        ▼
useFuturristic() ── useState('futurristic-mode')  ◄── setMode() mutations
        │
        ▼
plugin futurristic-init ── reactive useHead()
        │
        ├─► <html data-fu-mode="defend">
        └─► <link key="fu-mode-stylesheet" rel="stylesheet" href={active mode css}>
                │
                ▼
:root[data-fu-mode='defend'] { --fu-* tokens }   ← activates
                │
                ▼
components consume var(--fu-*)  →  restyled
```

Both the `data-fu-mode` attribute and the single `<link>` are driven by one reactive `useHead()` call, so `setMode()` swaps them together. Server-side rendering emits the correct attribute and link for the configured mode, so the initial paint has no flash of wrong-mode styling.

## Repo layout contract

```
src/
  module.ts                     # module entry; re-exports all public types
  runtime/
    types.ts                    # FuMode, FuConfig — source of truth for modes
    types/                      # per-domain public types (icon.ts, link.ts, *.generated.ts)
    composables/                # auto-imported (useFuturristic)
    plugins/futurristic-init.ts # mode → DOM binding
    components/                 # auto-registered, one file per component
    assets/
      shared/                   # mode-independent CSS only
      modes/<mode>/             # one folder per mode: index.css + category files
      icons/<set>/<name>.svg    # committed SVG sources
scripts/
  generate-fu-icon-types.mjs    # CLI: icon type generation (postinstall/prepack/dev:prepare)
  lib/scan-fu-icon-assets.mjs   # canonical scanner + TS emitter
  figma/                        # design-time export scripts + node maps
playground/                     # demo app; one page per mode
docs/specs/                     # this suite
tailwind-preset.cjs             # optional consumer preset
```

Gitignored: `src/runtime/types/icon-types.generated.ts` (regenerated by lifecycle scripts).

## Invariants index

The suite's spine. One line each; the owning doc holds the full rule and rationale.

| # | Invariant | Owner |
|---|---|---|
| I1 | Exactly one mode is active per document, expressed as `<html data-fu-mode>` | [01](01-style-modes-and-theming.md) |
| I2 | Every mode-file declaration is scoped to `:root[data-fu-mode='<mode>']` — never bare `:root` | [01](01-style-modes-and-theming.md) |
| I3 | Mode files contain custom-property declarations only — no element/class rules | [01](01-style-modes-and-theming.md) |
| I4 | Token parity: every mode defines the identical required token manifest | [01](01-style-modes-and-theming.md) |
| I5 | Raw color values live only in the primitives layer | [01](01-style-modes-and-theming.md) |
| I6 | Components are mode-agnostic: per-mode differences live in mode files (token-side) | [01](01-style-modes-and-theming.md) / [02](02-component-standards.md) |
| I7 | Components style exclusively via `--fu-*` tokens or local hook vars — no hardcoded visual values | [02](02-component-standards.md) |
| I8 | Every component: `inheritAttrs: false` + root `v-bind="$attrs"` + exported `I<Name>Props` | [02](02-component-standards.md) |
| I9 | Icons load as per-icon lazy chunks (`?component` dynamic import); never bundled eagerly | [03](03-icon-pipeline.md) |
| I10 | `icon-types.generated.ts` is generated, gitignored, never hand-edited | [03](03-icon-pipeline.md) |
| I11 | Exactly one mode stylesheet `<link key="fu-mode-stylesheet">`; inactive-mode CSS is never fetched | [04](04-css-delivery-and-performance.md) |
| I12 | The plugin's mode→stylesheet map uses static `?url` imports (`Record<FuMode, string>`) | [04](04-css-delivery-and-performance.md) |
| I13 | Mode CSS is never pushed to `nuxt.options.css`; only `assets/shared/` is global | [04](04-css-delivery-and-performance.md) |
| I14 | The `prefix` option renames components only — `fu-` classes and `--fu-` tokens are fixed | [05](05-module-config-and-dx.md) |
